## تحديث إدارة الشات الموحد

لوحة مستقلة للبث تجمع رسائل وتفاعلات Twitch وKick وTikTok، ولا تحتوي على مسابقة أو نقاط.

- زر ⋯ بجانب رسالة الدردشة يفتح الرد والحذف والتايم أوت والحظر وفك الحظر.
- صندوق إرسال يحدد منصة واحدة؛ الرد على رسالة يثبت منصة صاحبها حتى إلغاء الرد.
- الإجراءات تنفذ في قناة الحساب المفوّض فقط، ولا تنفذ على المنصات الأخرى.
- حذف رسالة من اللوحة يحدّث نوافذ الحساب ومصدر OBS بعد نجاح طلب المنصة.
- تيك توك عبر الموصل الحالي للاستقبال فقط؛ أدوات إدارته من تطبيق تيك توك.
- الحسابات المرتبطة سابقًا تحتاج «إعادة تفويض الحساب» من ربط المنصات لمنح الصلاحيات الجديدة. إعادة الاتصال وحدها لا تضيف صلاحيات.
- على مالك تطبيق Kick إتاحة chat:write وmoderation:ban وmoderation:chat_message:manage ضمن إعدادات التطبيق.
- فلاتر الكلمات في الإعدادات تخفي الرسائل محليًا وفي OBS فقط؛ لا تمثل حظرًا على المنصة.

التحقق: اختبارات محلية بطلبات منصات محاكية؛ لم تُجرَ عمليات على قنوات حقيقية. التشغيل الفعلي يتطلب إعداد الخادم ومفاتيح التطبيقات وتفويض حسابات القنوات.

# BSM Chat — نسخة تشغيل أولى

منصة عربية لعرض دردشات وتفاعلات Twitch وKick وTikTok داخل لوحة واحدة ومصادر OBS مستقلة لكل حساب.

## حالة التسليم

الكود مكتمل للتركيب والاختبار، وليس خدمة عامة منشورة بعد. النسخة السابقة المنشورة على chatgpt.site تظل معاينة منفصلة ولا تستضيف هذا الخادم. لا توجد مفاتيح حقيقية أو حسابات أو بيانات تجريبية ضمن الحزمة.

تم اختبار التسجيل والدخول وعزل الحسابات والإعدادات، وبث الرسائل لحساب واحد، ومنع التكرار، وتجديد رابط OBS، وانتهاء OAuth وتوقيع أحداث Kick وتشفير الرموز. لم يُجرَ اختبار حي بتفويض حسابات Twitch/Kick أو بث TikTok. واجهة الدخول عُرضت في المتصفح؛ رحلة الحساب كاملة اختُبرت عبر HTTP آليًا.

## أسرع طريقة للرفع

1. أنشئ مستودع GitHub جديدًا باسم `bsm-chat`، وارفع **محتويات** هذا المجلد إلى جذر المستودع، بحيث يظهر `package.json` و`server.js` مباشرة. لا ترفع مجلدًا يحتويهما من الخارج.
2. افتح Render واختر New → Blueprint واربط المستودع.
3. يتضمن `render.yaml` خدمة Node 24 وقرصًا دائمًا لحفظ الحسابات والإعدادات. هذه الخطة والقرص **مدفوعان**؛ راجع التكلفة المعروضة قبل Apply. لم يتم إنشاء خدمة أو شراء خطة عند تجهيز الحزمة.
4. ضع `PUBLIC_URL` على عنوان خدمة Render النهائي بدون `/` في النهاية. يجب أن يبدأ بـ `https://`. إذا احتجت إنشاء الخدمة أولًا لمعرفة العنوان، عدّل المتغير إلى العنوان الفعلي ثم أعد النشر.
5. يولّد Render متغير `APP_SECRET` تلقائيًا مرة واحدة. **احفظه ولا تغيّره**: يحمي مفاتيح OAuth وروابط OBS المخزنة. لا ترسله في المحادثة ولا تضفه إلى GitHub.
6. بعد النشر افتح `/healthz` للتأكد من استجابة الخادم، ثم افتح الموقع وأنشئ حسابًا. حسابات الاختبار المحلية لا تُنقل إلى الإنتاج.
7. أضف مفاتيح المنصات أدناه إلى Environment في Render وأعد النشر.

إذا لم تقبل واجهة Render معرّف خطة `0.5c-512mb`، اختر المعادل الحالي من لوحة Render. ملف Blueprint تحقق منه محليًا وفق مخطط Render عند التجهيز؛ لم يُطبق عبر Render CLI أو على حساب حي.

## Twitch — مطلوب من مالك المنصة مرة واحدة

أنشئ تطبيقًا سريًا (Confidential) من https://dev.twitch.tv/console/apps ثم اضبط OAuth Redirect URL ليطابق:

`https://YOUR-DOMAIN/auth/twitch/callback`

أضف إلى Render:

- `TWITCH_CLIENT_ID`
- `TWITCH_CLIENT_SECRET`

بعد ذلك، يستطيع كل ستريمر تسجيل الدخول إلى BSM Chat والضغط على «ربط حساب Twitch» والموافقة على قراءة دردشته وأحداثه. لا يحتاج كل ستريمر إلى إنشاء تطبيق خاص.

الصلاحيات المطلوبة: `user:read:chat channel:read:subscriptions bits:read moderator:read:followers`. تُستخدم EventSub WebSockets لكل صاحب قناة. يدعم الكود رسائل الشات، الاشتراك والتجديد والإهداء والمتابعة وBits والريد. بعض الأحداث لا تقبلها Twitch إلا للقنوات المؤهلة أو عند توفر صلاحياتها؛ تعرض الواجهة اتصالًا جزئيًا عند رفض أي منها.

## Kick — مطلوب من مالك المنصة مرة واحدة

أنشئ تطبيقًا من إعدادات المطور في Kick. اضبط Redirect URL:

`https://YOUR-DOMAIN/auth/kick/callback`

فعّل استقبال Webhooks في إعدادات التطبيق واضبط الرابط:

`https://YOUR-DOMAIN/webhooks/kick`

أضف إلى Render:

- `KICK_CLIENT_ID`
- `KICK_CLIENT_SECRET`

الصلاحيات: `user:read events:subscribe`. يستخدم الكود OAuth مع PKCE. يتحقق الخادم من توقيع RSA ومهلة الرسالة ويمنع تكرار وصولها. لا تظهر «متصل» قبل وصول أول حدث صالح؛ حالة الانتظار بعد إنشاء الاشتراكات أمر طبيعي.

الأحداث: `chat.message.sent`, `channel.followed`, `channel.subscription.new`, `channel.subscription.renewal`, `channel.subscription.gifts`.

## TikTok — تجريبي وغير رسمي

مكتبة `tiktok-live-connector` موصل غير رسمي؛ لا ينبغي اعتبارها API تجاريًا مضمونًا. قد يتطلب مزود التوقيع مفتاحًا أو اشتراكًا مستقلًا، وقد تتغير حدود الاتصال أو يتعطل الربط من خوادم الاستضافة.

- فعّل `ENABLE_TIKTOK=true` في Render بعد اختبار المزود.
- أضف `TIKTOK_SIGN_API_KEY` إذا كان مزود التوقيع يتطلبه.
- ابدأ البث في TikTok، ثم ضع اسم القناة من لوحة الربط واضغط اتصال.
- يدعم الشات والهدايا والقلوب والمتابعة والمشاركة. هدايا السلاسل تُحسب عند نهاية السلسلة حتى لا يتكرر احتساب الهدية.
- عند انتهاء البث أو فشل الاتصال تظهر الحالة الحقيقية؛ أعد الاتصال عند بدء البث. لا تُستخدم محاكاة بدل الرسائل الحقيقية.
- ربط اسم TikTok لا يثبت ملكية القناة في هذا الموصل؛ لا توجد عمليات إرسال أو تعديل أو إدارة حساب TikTok.

## OBS

بعد الدخول، اختر «مظهر البث وOBS»، ثم حدد الكل أو الدردشة فقط أو التفاعلات فقط وانسخ الرابط إلى مصدر متصفح OBS. احفظ اللون والحجم والخلفية من اللوحة. الإعدادات تُزامن إلى مصادر OBS المفتوحة.

الرابط يحتوي مفتاح قراءة مستقلًا داخل جزء `#`؛ لا تنشره. زر تجديد الرابط يُبطل الرابط القديم فورًا ويغلق اتصالاته. العرض يقتصر على الرسائل ولا يعطي صلاحيات إدارة الحساب.

## تشغيل محلي

يتطلب Node.js 24:

```bash
npm ci
```

انسخ `.env.example` إلى `.env` واضبط `APP_SECRET` بقيمة عشوائية (32 حرفًا على الأقل):

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
npm start
```

افتح http://localhost:3000. يتطلب Kick Webhook عنوان HTTPS عامًا للوصول من المنصة؛ الخادم المحلي وحده لا يكفي. استخدم عنوانًا عامًا مطابقًا لإعدادات OAuth عند اختبار الربط.

```bash
npm run check
npm test
```

## حدود هذه النسخة قبل الإطلاق الواسع

- خدمة واحدة وSQLite على قرص دائم، مع آخر 300 رسالة لكل حساب ولمدة أقصاها 24 ساعة؛ لا يوجد أرشيف دائم للمحادثات.
- حتى 10 نوافذ عرض متزامنة لكل حساب. يلزم اختبار تحميل وتحديد السعة قبل دعوة أعداد كبيرة.
- لا توجد استعادة كلمة مرور بالبريد أو توثيق بريد أو فوترة أو لوحة مسؤول أو إرسال رسائل أو حظر وحذف على المنصات. حددت النسخة بالقراءة فقط.
- كلمات الإخفاء والفلاتر تؤثر على عرض BSM Chat وOBS فقط.
- لا تعتمد على تخزين Render المؤقت؛ يجب استخدام القرص الدائم. لا تشغّل عدة نسخ على نفس قاعدة SQLite.
- استخدم نسخًا احتياطية صحيحة لـSQLite (Online Backup أو snapshot مدعوم) مع نسخة آمنة من `APP_SECRET`؛ نسخ ملف القاعدة منفردًا أثناء الكتابة قد يهمل WAL.
- افصل القناة من اللوحة أو ألغِ تفويض التطبيق لدى المنصة عند عدم الحاجة. تتوقف الأحداث أثناء تعطل الخادم وقد لا تعيدها المنصة.
- حفظ أسماء الحسابات وكلمات المرور مستمر على القرص. كلمات المرور مخزنة بـscrypt؛ جلسات الدخول HTTP-only ومدتها 7 أيام؛ رموز OAuth مشفرة بـAES-GCM.
